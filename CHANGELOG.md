# Changelog

## Unreleased

- Add `clementina mcp`, which serves the MCP server over stdio from the CLI, so the standalone executables run it without Node.js.
- Add `clementina --version`, which names a checkout build and its commit; `doctor` prints it and the path and version of each tool it finds.
- Add dev installs: `npm run dev:install` puts launchers for this checkout's `clementina` and `clementina-mcp` in `~/.clementina/dev/bin`, and `clementina-dev on|off|status` switches a shell between them and the installed tools.
- Remove `program.kind`. A project is described by its parts: an optional BASIC `program.entry` and an optional `build.assembly`, which now lists its own `sources`. With both, the load plan `BLOAD`s the PRG and then runs the BASIC program. Build results, `clementina build --json`, MCP and the debugger report `assembly`/`basic` parts instead of a kind; `create-game.mjs init` takes `--template`.
- Add `build.basic.memoryTop` and the `memoryTop` load-plan step, which lower BASIC's `MEMSIZ` so bank-0 RAM above it is free for code a BASIC program calls.
- Every build writes `memory-layout.json`: each part's place in CPU memory and MIA RAM next to the machine's areas, with overlaps as `build.layout.overlap` warnings. Overlapping asset slots are now a warning too.
- A load plan ending in a BASIC program also renders as a numbered bootstrap, ending with its `LOAD`.
- The VS Code extension opens `.s` and `.inc` files as Clementina Assembly: a 65C02/ca65 TextMate grammar that also highlights the runtime macros, routines and spec constants from the public includes (generated by `npm run generate:asm-grammar`), and gutter breakpoints for assembly and BASIC sources.

## 0.3.0-alpha.1

First alpha release. GitHub releases carry the standalone CLI executables, the VS Code extension (`.vsix`) and `SHA256SUMS`; npm packages are published under the `alpha` dist-tag.

- PRG files carry a 2-byte load-address header with no bank byte. Load plans pick each PRG bank with `BANK n:` and start the program with `BRUN`, `MIALOAD` steps no longer emit a length, and the BASIC tokenizer keeps hex digits after `$` (up to 6) raw instead of crunching `CD` or `DEF`, matching the ROM.
- Generate `clementina.inc` and `mia.inc` from `specs/` (`npm run generate:includes`) and put them on every assembly build's include path; the asset runtime uses MIA's names from them.
- Add automated package-content checks and CI for supported Node versions.
- Make the SDK npm packages publishable under GPL-3.0-only.
- Check assembler and emulator availability through `clementina doctor`.
- Add a physical hardware audio fixture and capture analysis workflow.
- Build packages through TypeScript project references (`npm run build` runs `tsc -b`; `npm run clean` removes output).
- Share `errorMessage`, `formatHex`, `isIntegerInRange`, and `SerialQueue` from `@clementina/core` instead of per-package copies.
- Export the default emulator executable and `CLEMENTINA_EMULATOR` lookup from `@clementina/emulator-client/node`.
- Raise `DebugSessionError` from BASIC debug sessions, matching assembly sessions.
- Ship the CLI as standalone executables for Linux, macOS, and Windows that need no Node.js install (`npm run build:binaries`; attached to tagged GitHub releases).
- Embed the ca65 runtime sources as `runtimeFiles` in `@clementina/runtime`; builds write them instead of copying from the package directory.
- Bundle the VS Code extension with its debug adapter and BASIC language server so the `.vsix` packages from the workspace (`npm run package` in `packages/vscode-extension`).
- Add `clementina project import` to turn a Studio session file into a new portable assembly project.
- Add `WaitTick`, `ReadPad` and `KeyHeld` to the runtime: frame timing from MIA's 60 Hz count, and held gamepad and keyboard input.
